# ADR0003: native Windows DNS-SD for T016

Accepted implementation choice by leader; fixed T016/REQ13-14/SPEC04 preserved, no new milestone/model/driver/cloud service. Mac still requires actual M6 Bonjour adapter and hardware evidence.

Initial mdns-sd0.21.4 was audited/downloaded; its command/browse/monitor channels are bounded but DNS cache maps/record vectors have no proved capacity. Identity slice therefore never created ServiceDaemon and kept mDNS unavailable. A bounded downstream table does not bound the upstream cache. Retain historical initial dependency audit, stop using/remove unused dependency rather than ship a false claim or fork/refactor unrelated upstream protocol code.

Use existing pinned windows0.62.2 platform Dns feature and OS DNS-SD APIs. Default construction does not browse/register/resolve/bind; explicit trusted Node userLAN opt-in with nonzero selected InterfaceIndex is mandatory. Native callback results are untrusted addressing only, copied with capped strings/property/record budgets into bounded nonblocking queue and finite TTL table. At most one browser/advertiser, bounded resolve operations, retained context/quarantine budget; never accept fingerprints via discovery or give remote mic/profile authority. OS DNS cache/temporary API allocation is outside app-owned queue proof and must remain disclosed; memory/runtime metrics still T026, no universal OS resource bound claim.

Microsoft [DnsServiceBrowse](https://learn.microsoft.com/en-us/windows/win32/api/windns/nf-windns-dnsservicebrowse) supports explicit interface and asynchronous callback; [callback docs](https://learn.microsoft.com/en-us/windows/win32/api/windns/nc-windns-dns_service_browse_callback) require freeing returned RR sets. [BrowseCancel](https://learn.microsoft.com/en-us/windows/win32/api/windns/nf-windns-dnsservicebrowsecancel) documents final ERROR_CANCELLED callback, so lifetime uses terminal completion, not assuming API return equals quiescence. [Register](https://learn.microsoft.com/en-us/windows/win32/api/windns/nf-windns-dnsserviceregister) is asynchronous/process lifetime tied; [Resolve callback](https://learn.microsoft.com/en-us/windows/win32/api/windns/nc-windns-dns_service_resolve_complete) requires DnsServiceFreeInstance.

Any cancel/de-register failure or unknown completion retains at most fixed process-budget context and denies new operations when budget exhausted; do not free callback context early or claim cleanup PASS. API struct/string/cancel memory pinned until terminal completion, records/instances released once, no panic across FFI. Native API adapters compile/test with injected functions first; no actual network operation or firewall change as dependency setup. Actual DNS-SD smoke needs scoped explicit interface/operation and recorded command later; no LAN/Mac proof inferred.

Identity/pin/signature/DPAPI remain unchanged; TLS possession/mutual connection T017, Node revocation/session cleanup T018, actualLAN T020. Manual address remains independent fallback when discovery unavailable, no trust bypass. Removal of mdns dependency is initial selection correction, not silent reduction of discovery acceptance or unrelated dependency upgrades.
