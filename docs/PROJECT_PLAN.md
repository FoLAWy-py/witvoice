# 固定项目计划：7 个里程碑 / 35 个顶层任务

**本计划没有隐含 M7，也没有无限优化阶段。默认本次 Windows 开发授权执行至 M5。M6 仍是完整项目的必需里程碑，不会被删掉。**

同一个里程碑可并行执行已经满足依赖的非冲突任务。下一里程碑的低风险设计准备可提前做，但不能越过验收门把未通过状态叫完成。

## 关闭任务需要什么

代码真实存在、所需测试执行、证据归档、独立评审无S0/S1，并更新任务与需求映射。每个任务可以细化最多5个短检查项，但不得另起不受限制的顶层backlog。新增范围必须进入change request。

证据报告使用`templates/EVIDENCE.json`，人工项明确标manual；证据文件归属实际提交/构建，不得复用旧commit报告掩盖回归。reviewer不修改被评代码；修复回到原owner。

## 有限修复与阻塞策略

每个任务最多3轮正式review修复循环。第三轮仍有S0/S1或硬门槛失败时，停止该任务的盲目尝试，记录最小复现、已试假设、影响与明确解阻动作。不要调低门槛、屏蔽测试或换名称绕过。leader可以推进无依赖的其他固定任务，不能声称整个里程碑通过。

M0模型探索有更严格预算：主候选最多两次有证据的兼容修复，最多一次替代候选。界面非功能视觉打磨最多两轮HCI修订；不会无限增加动画和控件。

达到本轮上下文/额度/权限边界时，先停止子agent写入、整合可验证结果、写HANDOFF与next_task，再如实结束。不能保证一次会话能做完全部工程，也不能只输出下次计划而完全不执行当下可做任务。

## 三种合法终止输出

1. **WINDOWS_DELIVERED**：M0–M5通过；提供Windows产物、真实结果和M6尚未验证列表；不再默认扩展工作。
2. **COMPLETE**：M0–M6全部通过；完整双向真机证据齐全；停止新功能与重构。
3. **BLOCKED**：外部前置条件或有限修复预算阻塞；报告已完成部分、最后可信版本、最小解阻动作与下一任务。不能把BLOCKED写成DONE。

## 范围变更

用户新增要求 → leader生成CR → 列受影响REQ/任务/验收与替代项 → 用户批准 → 更新规格版本/账本。非功能小实现决定由leader写ADR即可；不需要为每个内部细节询问用户。

公开商业发行、自研驱动、增加第二模型、WAN、移动端等不在这35个任务内，不能在终审时突然追加成“必须做完才算完成”。
