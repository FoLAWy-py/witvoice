# 工程项目 SPEC

规格 ID：VC-SPEC-2026-10-04。所有 MUST 表示必须验收；SHOULD 表示需要记录偏离理由的建议。
本文件是需求基线；详细设计见 `spec/`。用户后续明确变更优先，但 leader 必须记录影响，不得静默改写历史验收结果。

## 1. 产品目标

开发一个稳定、美观、本地优先的桌面实时 **Speech → Speech Voice Conversion** 变声器。

用户从物理麦克风输入语音，系统使用获授权的目标音色转换，结果经本机虚拟音频输入端点供聊天、会议、游戏或录制程序选择。处理可以在本机，也可以在同一局域网的另一台已配对计算机。

必须实现的三条链路：

```text
Windows 物理麦克风 → Windows 真实 VC → Windows 虚拟麦克风
Windows 物理麦克风 → LAN → Mac 真实 VC → LAN → Windows 虚拟麦克风
Mac 物理麦克风 → LAN → Windows 真实 VC → LAN → Mac 虚拟麦克风
```

完整交付同时包含 Mac 本地处理能力，作为第二条链路的计算能力与平台验收的一部分。两种远程方向分别验证，不要求同时运行。

## 2. 明确决策与优化

**开发宿主**：Windows 11 x64、PowerShell、原生 MSVC 工具链。不把 WSL 音频或 Linux 容器跑通当 Windows 原生验收。官方 Codex 支持原生 Windows 工作流；实际权限仍由用户的本机配置决定。[S03]

**范围**：每个节点同一时间最多一个活跃音频 session；Capture 与 Sink 在同一台机器，Compute 可以远端。第三台独立 Sink、多客户端共享 GPU、WAN、NAT 穿透均不实现。

**模型**：MeanVC2 是优先验证候选，不是免测试的承诺。M0 选择并锁定一个真实 zero-shot VC 引擎及完整依赖。不能同时建设 MeanVC2、RVC、X-VC 三套生产实现。RVC 固定音色不等价于本规格的 zero-shot 要求，不得偷偷替代。X-VC 只能在 MeanVC2 的可复现阻塞出现后作为一次有记录的候选替换。[S08][S09]

**驱动**：本轮使用用户从官方渠道自行安装的虚拟音频设备作为外部前置条件。Windows 本轮明确采用用户已自行安装的 VB-CABLE，Mac 以 BlackHole 2ch 为参考。Steam Streaming Microphone 不再作为本轮路由候选；仅保留历史测试证据。不捆绑、改名或假设其可商业再分发；商业授权另行审查。虚拟设备未安装必须显示阻塞，不能用系统扬声器冒充虚拟麦克风。[S10][S11]

**推理**：先保留经过验证的 Python worker，不把 ONNX、TensorRT、CoreML 原生化设为完成必要条件。只有通过同一音质/状态/延迟回归的后端才可上架。MPS/CoreML 存在不等于特定模型可用。[S07]

**IPC**：本地音频先使用受访问控制的独立二进制 Named Pipe / Unix Domain Socket，端到端有界、无实时回调等待。48kHz mono float32 单向约 192,000 B/s，这是格式算术，不是系统性能实测。不得仅为了“零拷贝”先建设跨语言共享内存原子协议；只有 IPC 证据显示不达门槛，才通过 ADR 引入共享内存。

**交付类型**：内部可安装测试版本，不自动承担公开商业发行、商店审核或自研驱动签名。公共发行状态必须与功能验收状态分开。

## 3. 技术栈

| 部分 | 定案 | 禁止的越界 |
|---|---|---|
| UI | React + TypeScript；Tailwind；一套无障碍组件基元；轻量动画 | 不在 WebView 中处理 PCM/模型 |
| 桌面壳 | Tauri 2；窄权限 IPC | 不加载远程网页作为主 UI，不暴露任意 shell |
| 后台节点 | Rust 独立用户态 `voice-node` | 不依赖 UI 渲染线程存活 |
| 音频 | Rust；Windows WASAPI；Mac Core Audio；可使用 CPAL 作为薄适配 | 不为抽象而实现第二套同功能音频框架 |
| 推理 | 选定的 Python + PyTorch worker；后端按实测 capabilities 宣告 | 不默认承诺 CPU/MPS/CUDA 全支持 |
| 局域网 | Quinn / rustls；QUIC Streams 控制，Datagrams 媒体 | 不为每个音频帧做 JSON/base64 |
| 持久化 | SQLite + 版本化迁移；模型/音色使用内容摘要与 manifest | 不写入 Git 中的用户数据 |
| 测试 | Rust tests；Python pytest；TS 测试；桌面 E2E；实机 HIL | 不用 mock 结果代替真实平台证据 |

所有依赖在 M0/M4 按实际兼容组合锁定版本。使用明确 lockfile，不臆造“最新”版本或自动更新整套依赖。

## 5. 不在本轮实现

自研 Windows 驱动、Mac 音频插件；多模型市场；模型训练；用户账户/付费/云后台；自动公网服务；移动端；多节点拓扑编辑器；Linux 产品发行；ASIO 专门优化；A/B 双引擎无缝热切换；声纹身份验证；未经请求的语音转写或 TTS；自动根据性别推断音高；通用 agent 框架。

可保留窄接口，不创建没有调用方的空框架、占位服务、虚假页面或大量空 crate。

## 6. 不可破坏的不变量

I-01：任何未批准连接、失败、丢帧、模型未就绪均不得放行原始麦克风到输出。
I-02：音频回调不等待 UI、Python、网络或互斥锁。
I-03：网络或推理再慢也不能无限排队；过期音频必须丢弃。
I-04：UI 不能先显示 Running 再去尝试启动，状态来自 Node 的确认。
I-05：被标注为 converted 的数据必须来自选定且验证过的真实引擎；测试旁路仅存在于测试构建。
I-06：旧 session/epoch 的结果不能在新音色、新设备或重连后播放。
I-07：指标的测量边界公开；不能把推理耗时或 RTT 冒充总延迟。
I-08：已通过的里程碑不能因新代码回归仍保持“通过”；状态要重开。

## 7. 最终成功定义

Windows 开发轮成功：M0–M5 全部通过；M6 若没有真机证明仍 Pending/Blocked；状态是 `WINDOWS_DELIVERED`。

完整项目成功：M0–M6 全部通过；三条必需链路有同一版本的真实记录；无未关闭 S0/S1；所有必需测试通过；内部交付包和复现说明齐全。此时状态才是 `COMPLETE`。

无论任何阶段，一旦达到当前授权终点就停止新增功能、停止无限重构、停止自动扩展里程碑。
