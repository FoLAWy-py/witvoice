# 02 · 音频、实时约束与故障语义

## 1. 采样格式与实际端点

内部 bus：48kHz、mono、float32。网络 bus：48kHz、mono、PCM16 little-endian。模型输入/输出使用各自已验证原生采样率；只在边界 resample，禁止重复串联无意义重采样。

实际音频端点可能使用 stereo、44.1kHz 或其他格式。必须协商，不声称硬件一定原生支持 48kHz mono。2ch 虚拟设备需要明确 mono → 双通道映射，默认两通道复制同一 mono 信号；增益与限幅在映射前完成。

Windows 路由示例：Node 把处理后声音写入 **CABLE Input（播放/render 端点）**；第三方应用选择 **CABLE Output（录音/capture 端点）**。不要把两者名称的 Input/Output 误认为用户话筒方向。[S10]

Mac 路由示例：Node 输出到 BlackHole 的输出侧；第三方应用选择 BlackHole 输入侧。设备按持久 ID/UID 保存，名称只供展示；移除后不能选一个同名物理麦克风作替代。[S11]

## 2. 线程与缓冲

Capture callback → capture SPSC ring → DSP/chunk worker → inference/transport → playout assembler → playout SPSC ring → output callback。

回调只能读写固定容量缓冲和轻量原子状态；允许为静音填零；禁止常规堆分配、锁等待、日志格式化、网络、文件、数据库、GUI IPC、Python 和 GPU 同步。

所有队列定义 capacity、target occupancy、maximum age、overflow policy。**分配了 200ms 容量不表示要等待满 200ms 才处理。** 初始目标：capture 排队 ≤20ms；输出目标排队 10–30ms；整体过期由 session 的延迟预算控制。容量和目标在诊断中分开展示。

音频线程故障不能引发 panic 穿越 FFI 边界。记录原子错误状态后由普通线程报告。MMCSS 等调度策略通过平台适配使用，不能代替无阻塞设计。

## 3. 时钟与时间线

以采集端 source sample counter 为主时间线；每次重连、重新准备、设备变化都更新 epoch。Compute 节点不打开自己的声卡，不引入第三个音频硬件时钟。

输入、虚拟输出、监听输出可以有不同实际时钟。输出侧观察目标缓冲占用，采用小幅自适应重采样（ASRC）消化漂移；不靠不断丢整块正常语音维持平衡。初始纠偏安全范围 ±1000 ppm，超出持续范围视为配置/设备错误，而不是无限扩大速度变换。

监控与虚拟麦克风各有自己的 playout buffer 与时钟跟踪；监听断开不能阻塞虚拟输出。8 小时合成时钟偏移测试覆盖 ±150ppm、±500ppm。

VAD 只作为统计/可选模型提示；不得以“无语音”为由删除源时间，压掉笑声/轻声、改变包序列或破坏模型上下文。降噪默认关闭；只有用户显式打开，并通过质量回归后才应用。

## 4. 缺帧与故障

少量缺失使用有界衰减/短交叉淡化或静音；不要假设 PCM 自带 Opus 那类丢包隐藏。禁止无限重复上一个音节。丢失过大使模型状态失配时，丢弃积压、递增 epoch、重新 warm/prime，再按恢复规则进入 Ready。

任何 underflow 必须单独计数，不能因填了静音就记作“零丢帧”。计划静音（Mute/Idle）和故障静音使用不同计数器。

**默认 fail-closed：** worker OOM/crash、远端断连、音色失败、格式异常、证书变更、设备丢失、媒体过期，都只能输出静音，不能切回原声。

收到 Stop/Mute 后立即使输出治理层失效，不依赖控制消息成功传到远端。对应本机确认到虚拟输出提交零音频应 ≤50ms；已在 OS/声卡内排队的音频单独记录实际尾音延迟，不虚报为 0。

网络输出连续缺帧达到配置期限时进入 FailedMuted；短时 PLC 最长 30ms。不得在重连后回放断线期间积累的输入/输出。

## 5. 启动与切换

启动：权限 → 明确设备 → 模型预热 → 音色校验 → 网络信任/租约（如有）→ 输出缓冲准备 → 源端用户 Start → 采集。

切换音色/设备/节点：淡出并静音 → 停止旧 epoch → 清空旧队列 → prepare 新配置 → Node 确认 Ready → 在当前用户授权范围内恢复。遇到新远端或新增原始音色传输必须重新确认。不得依赖 simultaneous 双模型加载实现“零延迟切换”。

Monitor 默认关闭。用户打开时提示耳机建议；不要把“检测到输出设备名称含 Headphone”当防啸叫保证。禁止使用正在输出的虚拟电缆作为物理输入，防止反馈环。

退出并停止先关闭源采集与输出权限，再结束网络和 worker；不能等慢 worker 正常退出才静音。
